# PRD — «Домовой»

## 1. Цель продукта

**Домовой** — персональный игровой слой внутри X5, который автоматически использует историю покупок пользователя, чтобы:

- показывать реальную выгоду от X5 Клуба;
- давать релевантную причину выбрать X5 для следующей покупки;
- связывать отдельные покупки в постоянный progress loop.

Пользователь ничего не загружает вручную: покупки с картой X5 автоматически попадают в историю.

### Core flow

**покупка → чек попадает в профиль → анализ привычек → обновление Домового и статистики → персональная цель/выгода → следующая покупка → новый прогресс**

## 2. Customer Jobs

### Job 1 — быстро найти релевантную выгоду

Когда мне снова нужно купить продукты, я хочу быстро понять, есть ли сейчас в X5 что-то выгодное именно для меня, чтобы не тратить время на просмотр множества акций.

**Гипотеза решения:** показывать одно главное персональное предложение/челлендж на основе истории покупок.

### Job 2 — понимать пользу программы лояльности

Когда я регулярно пользуюсь X5 Клубом, я хочу понимать, сколько пользы уже получил, чтобы видеть смысл продолжать им пользоваться.

**Гипотеза решения:** показывать фактическую экономию, прогресс и развитие Домового.

### Job 3 — иметь дополнительную причину выбрать X5

Когда мне снова нужны продукты, я хочу получить релевантную дополнительную причину выбрать X5, а не альтернативу.

**Гипотеза решения:** персональные цели немного выше привычного поведения пользователя.

## 3. Основной интерфейс

### Home / Домовой

Показываем:

- Домового;
- level / XP;
- текущее состояние;
- экономию за месяц;
- один персональный insight;
- **1 главный челлендж / offer**;
- progress;
- `Почему это мне?`;
- `Все цели`.

Пример:

**Домовой · уровень 7**

В сентябре вы сэкономили 1 240 ₽

**Цель недели**

Обычно у вас 2 покупки в неделю.

Сделайте 3 до воскресенья.

**2 / 3**

+50 XP + 30 баллов

## 4. Автоматическая обработка покупки

Новый чек приходит автоматически после покупки с картой X5.

Система:

1. добавляет чек в историю;
2. пересчитывает профиль пользователя;
3. обновляет savings;
4. обновляет progress целей;
5. начисляет XP;
6. меняет состояние Домового;
7. при выполнении цели начисляет reward.

Для demo используем техническую кнопку **`Simulate new purchase`**.

## 5. Персональные цели

На Home — **1 hero challenge**.

На экране `Все цели` — ещё максимум 2.

### MVP-типы

**Frequency**

Обычно 2 покупки в неделю → цель 3.

**Category**

Пользователь регулярно покупает молочные продукты → цель по этой категории.

**Discovery**

Пользователь часто покупает йогурты → предложение из близкой категории.

Каждая цель содержит:

`type / baseline / target / progress / deadline / reward / rationale`

## 6. Как формируется предложение и reward

### Pipeline

**чеки → user features → допустимые offers/challenges → персонализация → economics engine → LLM → показ пользователю**

### 1. User features — обычный код

Из чеков считаем:

- frequency;
- recency;
- average basket;
- promo sensitivity;
- category affinity;
- purchase cadence;
- realized savings;
- favourite store;
- challenge history.

### 2. Candidate engine — обычный код

Определяет, **что вообще можно предложить** пользователю.

Например:

- есть headroom по frequency → `Frequency challenge`;
- сильная affinity к категории → `Category challenge`;
- есть подходящее активное промо → персональный offer.

### 3. Personalization

AI/recommender ранжирует допустимые варианты и выбирает:

- 1 hero option;
- до 2 side options.

### 4. Economics / Reward Engine — обычный код

Определяет:

- target относительно baseline;
- можно ли выдавать денежную награду;
- максимальный размер reward.

Пример:

`baseline = 2 покупки/неделю`

`target = 3`

`avg basket = 600 ₽`

`expected incremental margin = 90 ₽`

Если правило X5:

`reward ≤ 40% expected incremental margin`

то максимальная стоимость reward:

`36 ₽`

Система может выдать, например, **30 баллов**.

Если используем существующее промо X5, engine выбирает подходящий offer из доступного пула.

### 5. LLM

LLM отвечает только за:

- текст от лица Домового;
- explanation;
- tone of voice;
- персональный insight.

Например:

> Домовой заметил, что вы покупаете молочные продукты примерно раз в 6 дней. Поэтому на этой неделе он выбрал цель именно по этой категории.

LLM **не назначает размер скидки или reward**.

## 7. «Почему это мне?»

Для каждой рекомендации пользователь может открыть explanation.

Пример:

> За последние 8 недель вы покупали молочные продукты 6 раз, обычно каждые 5–7 дней. Поэтому эта цель связана именно с этой категорией.

Explanation должен основываться на рассчитанных user features.

## 8. Моя статистика

Показываем:

- savings за месяц;
- покупки за период;
- average basket;
- top-3 categories;
- streak;
- выполненные goals;
- XP / level;
- 1–2 insights.

Без сложного BI.

## 9. Business / PM view

PM X5 должен видеть:

- user features;
- выбранный offer/challenge;
- rationale;
- baseline;
- target;
- reward;
- expected incremental effect;
- fraud score;
- result.

## 10. Synthetic Data

### Для разработки

100–500 пользователей.

### Для simulation

5–10 тыс.

История на пользователя: 8–12 недель.

Минимальные данные:

`user_id`

`receipt_id`

`timestamp`

`store`

`products`

`categories`

`regular_price`

`paid_price`

`discount`

`points`

Пользователи должны отличаться по:

- frequency;
- average basket;
- категориям;
- promo sensitivity;
- shopping cadence.

## 12. Demo flow

1. Открываем Домового.
2. Показываем savings + персональную цель.
3. Нажимаем `Почему это мне?`.
4. Показываем данные, на которых основана рекомендация.
5. Симулируем новую покупку.
6. Домовой автоматически «съедает» чек.
7. Обновляются XP, savings, state и challenge progress.
8. Показываем PM view.
9. Показываем simulation на 5–10 тыс. пользователей:
   - relevance hit rate;
   - frequency control vs treatment;
   - reward cost;
   - incremental margin;
   - antifraud precision.
